# Launch Sub-Agent (OpenClaw Skill — gateway-loaded)

## What this skill does

When the OpenClaw gateway receives a spawn-agent request (from a pi
session shelling out to `openclaw agent --message`), this skill performs
the actual SkyPilot launch + registers the new agent with the main-box
collector.

This is the **only** path that creates sub-agent boxes. Sessions request
spawns; the gateway executes them.

## Trigger

A message of the form:

```json
{"intent":"spawn-agent","config":{"model":"...","effort":"high","reason":"..."},"name":"research-box"}
```

## Steps

1. **Parse + validate the config.** Read `model`, `effort`, `urgency`,
   `resources`, `name` from the request. Apply autonomy rules: if the
   gateway's autonomy is `guided`, confirm with the user before launching
   (the request must include a `reason`); if `semi` or `full`, proceed.

2. **Generate the agent token** (per-agent A2A bearer secret). The token
   is written to `~/.orchestra/agent-token` on the new box at launch
   time (baked into the rendered YAML).

3. **Render the SkyPilot YAML:**

   ```bash
   python3 ~/orchestra/tree-view/gen-agent-yaml.py \
     --name "$NAME" \
     --config "$CONFIG_JSON" \
     --parent-url "$ORCHESTRA_PARENT_URL" \
     --collector-url "$ORCHESTRA_COLLECTOR_URL" \
     --out /tmp/agent-$NAME.yaml
   ```

   `$ORCHESTRA_COLLECTOR_URL` is `http://agent-main-box:7777` (the
   main-box collector). `$ORCHESTRA_PARENT_URL` is this gateway's own
   bridge URL.

4. **Launch the box:**

   ```bash
   sky launch --infra "$SKY_INFRA" -c "agent-$NAME" -y /tmp/agent-$NAME.yaml
   ```

   The cluster name `agent-$NAME` is how the collector discovers it via
   `sky status` (the `agent-` prefix is the convention).

5. **Register the edge with the collector.** The new box registers itself
   via `POST /tree/node` (in its `run` block), but the **edge**
   (parent→child) is owned by the parent (Design §5 — children cannot
   rewrite their own lineage). So the gateway POSTs the edge:

   ```bash
   curl -s -X POST "$ORCHESTRA_COLLECTOR_URL/tree/edge" \
     -H "Content-Type: application/json" \
     -d "{\"parent_id\":\"$SELF_ID\",\"child_id\":\"agent-$NAME\",\"bridge_url\":\"http://agent-$NAME:8080/\"}"
   ```

   `$SELF_ID` is this agent's node id (e.g. `agent-main-box`).

6. **Reply to the caller** with the new agent's `bridge_url`:

   ```json
   {"ok": true, "bridge_url": "http://agent-research-box:8080/", "agent_id": "agent-research-box"}
   ```

## Error handling

- If `sky launch` fails, reply with `{"ok": false, "error": "..."}` and
  do NOT register the edge. The cluster may partially exist — run
  `sky down -y "agent-$NAME"` to clean up.
- If the collector is unreachable, the box still launches but the TUI
  won't show it until the collector's `sky status` reconciliation picks
  it up as an orphan (within 60s). Log a warning but don't fail the
  launch — the box is useful even if the tree store lags.

## Token security

The agent token is generated by `gen-agent-yaml.py` and baked into the
YAML. It's written to `~/.orchestra/agent-token` (mode 600) on the new
box. The collector holds the token registry (future: the TUI reads the
registry to make authenticated A2A calls). Never log the full token.
